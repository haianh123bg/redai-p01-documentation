## Các loại nhà cung cấp có thể tạo

| Loại | Dùng khi |
| --- | --- |
| Tích hợp tùy chỉnh | Cần kết nối một API riêng và tự khai báo xác thực, biến dữ liệu, URL cùng HTTP Mapping. |
| Google Cloud | Cần kết nối Google Cloud Project bằng OAuth Credentials JSON để sử dụng OAuth với các dịch vụ Google. |
| LLM tùy chỉnh | Cần bổ sung nhà cung cấp LLM và khai báo từng model mà nhà cung cấp hỗ trợ. |

## Tạo tích hợp API tùy chỉnh

### Khai báo thông tin cơ bản

| Bước | Thao tác |
| --- | --- |
| 1 | Chọn tab **Tích hợp tùy chỉnh**. |
| 2 | Nhập **Tên hiển thị** và chọn ảnh nhận diện nếu cần. |
| 3 | Chọn **Loại xác thực** phù hợp với API. |
| 4 | Tại **Biến dữ liệu**, chọn biểu tượng <img src="https://api.iconify.design/lucide:plus.svg?color=%23ff3333" width="16" alt="" /> **(Thêm biến dữ liệu)** để khai báo các giá trị người dùng phải nhập khi tạo kết nối. |
| 5 | Với từng biến, khai báo tên hiển thị, key, kiểu dữ liệu, trạng thái bắt buộc nhập và hướng dẫn lấy giá trị theo biểu mẫu. |

Các cơ chế xác thực có thể xuất hiện trong danh sách gồm **Basic**, **Bearer**, **API Key** và **Custom**. Chỉ chọn cơ chế mà API đích thực sự hỗ trợ.

> **Cảnh báo:** Không nhập credential thật vào nội dung mẫu, mô tả hoặc hướng dẫn công khai. Credential chỉ được nhập khi người dùng tạo kết nối từ provider.

### Sử dụng biến dữ liệu

Trong phần **Cách sử dụng tích hợp**, RedAI dùng cú pháp `{{KEY}}` để chèn giá trị từ biến dữ liệu vào cấu hình. Ví dụ:

- `{{accessToken}}`
- `{{baseUrl}}`
- `https://{{prefix}}.example.com`

Key trong cú pháp phải trùng với key đã khai báo tại **Biến dữ liệu**.

### Cấu hình HTTP Mapping

Nhập URL tại **Base URL / Prefix mapping**. Có thể dùng URL đầy đủ hoặc ghép biến vào URL, ví dụ `{{baseUrl}}` hoặc `https://{{prefix}}.example.com`.

Sau đó cấu hình các tab cần thiết:

| Tab | Nội dung cần khai báo |
| --- | --- |
| Transform biến dữ liệu | Tạo biến dẫn xuất từ một hoặc nhiều biến nguồn trước khi dùng trong request. |
| Headers | Khai báo HTTP header và giá trị tương ứng. |
| Query Params | Khai báo tham số được gắn trên URL. |
| Body | Khai báo request body. |
| Cookies | Khai báo cookie nếu API yêu cầu. |

Chỉ cấu hình các phần mà API đích yêu cầu. Key được dùng trong URL, Header, Query Params, Body hoặc Cookies phải khớp với biến dữ liệu hay biến transform đã khai báo.

### Tạo biến transform

Luồng transform trên giao diện là:

`Source Keys` → `Operation` → `Transform` → `{{variableName}}`

| Bước | Thao tác |
| --- | --- |
| 1 | Chọn tab **Transform biến dữ liệu**. |
| 2 | Chọn biểu tượng <img src="https://api.iconify.design/lucide:plus.svg?color=%23ff3333" width="16" alt="" /> **(Thêm transform)**. |
| 3 | Nhập **Tên biến** sẽ nhận kết quả transform. |
| 4 | Chọn **Kiểu Transform**. |
| 5 | Chọn **Phép toán**: **None (Lấy key đầu tiên)** hoặc **Concat (Nối các giá trị)**. |
| 6 | Chọn biến nguồn theo biểu mẫu. |

Ví dụ được giao diện minh họa: kết hợp `username:password`, sau đó chuyển thành Base64 để dùng cho Basic Authentication.

### Lưu nhà cung cấp

Sau khi hoàn tất thông tin cơ bản, biến dữ liệu và HTTP Mapping, chọn biểu tượng <img src="https://api.iconify.design/lucide:check.svg?color=%23ff3333" width="16" alt="" /> **(Lưu/Xác nhận)** ở cuối màn hình.

## Tạo Google Cloud Project

### Chuẩn bị trên Google Cloud

| Bước | Thao tác |
| --- | --- |
| 1 | Chọn tab **Google Cloud**. |
| 2 | Tại **Bước 1: Copy Redirect URL**, chọn biểu tượng <img src="https://api.iconify.design/lucide:copy.svg?color=%23ff3333" width="16" alt="" /> **(Sao chép)**. |
| 3 | Trong Google Cloud Console, mở **APIs & Services** > **Credentials**. |
| 4 | Chọn **Create Credentials** > **OAuth client ID**. |
| 5 | Tại **Application type**, chọn **Web application**. |
| 6 | Dán Redirect URL đã sao chép vào **Authorized redirect URIs**. |
| 7 | Mở **OAuth consent screen**, chọn **PUBLISH APP** để chuyển từ Testing sang Production và xác nhận publish. |
| 8 | Tại **Bước 3: Bật Required APIs**, bật các API mà dự án cần sử dụng. |

Giao diện có nút **Mở OAuth Consent Screen** và **Bật ngay** để điều hướng đến khu vực tương ứng trên Google Cloud.

### Tải Credentials JSON lên RedAI

| Bước | Thao tác |
| --- | --- |
| 1 | Sau khi tạo OAuth client ID, tải tệp JSON từ Google Cloud Console xuống thiết bị. |
| 2 | Quay lại RedAI và nhập **Tên hiển thị**. |
| 3 | Tại **OAuth Credentials JSON**, kéo thả tệp hoặc chọn khu vực **Chọn file JSON**. |
| 4 | Chọn biểu tượng <img src="https://api.iconify.design/lucide:check.svg?color=%23ff3333" width="16" alt="" /> **(Lưu/Xác nhận)**. |

> **Cảnh báo:** OAuth Credentials JSON chứa thông tin nhạy cảm. Không gửi tệp qua hội thoại, không chèn nội dung tệp vào tài liệu và không công khai tệp.

## Tạo nhà cung cấp LLM tùy chỉnh

### Khai báo provider và danh sách model

| Bước | Thao tác |
| --- | --- |
| 1 | Chọn tab **LLM tùy chỉnh**. |
| 2 | Tại **Thông tin nhà cung cấp LLM**, nhập **Tên provider**. |
| 3 | Tại **Danh sách Models**, thêm model mới. |
| 4 | Mở model để hiển thị panel **Cấu hình model**. |
| 5 | Nhập **Model ID** đúng với định danh mà API của provider chấp nhận. |
| 6 | Chọn **Input modalities** mà model hỗ trợ. |
| 7 | Mở **Cài đặt nâng cao** và khai báo các giới hạn, tham số cùng tính năng tương ứng. |

### Các nhóm cấu hình model

| Nhóm | Nội dung |
| --- | --- |
| Thông tin cơ bản | Model ID và input modalities. |
| Runtime | Cấu hình vận hành được biểu mẫu hỗ trợ. |
| Max tokens | Giới hạn số token đầu ra của model. |
| Context window | Dung lượng ngữ cảnh model hỗ trợ. |
| Sampling parameters | Các tham số sampling được provider cho phép. |
| Tính năng | Các feature mà model hỗ trợ. |
| Use Responses API | Bật khi provider và model hỗ trợ cơ chế Responses API. |

Có thể khai báo nhiều model trong cùng một provider. Thực hiện cấu hình riêng cho từng model rồi chọn biểu tượng <img src="https://api.iconify.design/lucide:check.svg?color=%23ff3333" width="16" alt="" /> **(Lưu/Xác nhận)**.

> **Lưu ý:** Không bật tính năng hoặc nhập giới hạn cao hơn khả năng thực tế của API/model. Cấu hình sai Model ID, modality hay feature có thể làm model không sử dụng được.
